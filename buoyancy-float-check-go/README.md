## Description
Three-step **bespoke Go package `buoyancy`** with package-defined conventions (not generic textbook) and increasing difficulty. Distinctive identifiers `FrustumObject`, `StratifiedFluid`, `DiveResult`, `MinimumVolumeFraction`, `CrushDepth`, `CompressibleObject`, `SubmersionResult`, `CylinderObject`, `SphereObject`, `BuoyancyReport` returned **zero hits** in public Go package search during novelty check, confirming novel composition.

**Step1 (1_basic_float_check) HARDENED v2 (significantly harder):** Package-defined float/sink/neutral with tolerance-aware neutral boundary `|rho_obj - rho_fluid| <= Tolerance` where `Tolerance=1e-9` must be referenced via constant (AST check) in **three** functions (CheckBuoyancyByDensity, ApparentWeight, RequiredBallastMass). Plus new geometries:
- **Cylindrical object** `V=πR²H` Pi trap (R=1,H=1 → π not 1), diameter vs radius 4x confusion trap, inverse DRY trap: `Volume()` must NOT check Mass (geometry independent of mass, but Validate() does). Mass=0 Radius=1 Height=1 → Volume should be π not error.
- **Spherical object** `V=4/3 πR³` 4/3 factor trap (R=1 → 4.18879 not 3.14159 not 1), inverse trap Mass=0 should still return 4/3π.
- **Apparent weight** with package-defined tolerance-zeroing: if `|rho_obj - rho_fluid| <= Tolerance` → apparent weight exactly 0 (not epsilon), else `(Mass - rho*V)*g` using passed g, not StandardGravity (Mars 3.7 trap). Must reference Tolerance constant.
- **Required ballast** for neutral: `ballast = rho*V - Mass` mass to add (positive) or remove (negative), but with same tolerance-zeroing: within 0.9*Tol → exactly 0, not small 0.9*Tol*V. Must reference Tolerance.
- **BatchCheckBuoyancy** with order preservation via Index, nil→non-nil empty slice via explicit `make(...,0)` Go idiom (nil slice fails), invalid object → State="invalid" continue, fluid invalid → nil,error immediate, g invalid → nil,error containing "gravity", g param usage not StandardGravity.
- **Overflow detection**: package requires post-operation Inf/NaN check after `Mass/Volume`, `πR²H`, `4/3πR³`, `rho*V*g`, `mass*g`, `(Mass - rhoV)*g`, `rhoV - Mass`. Finite inputs like `1e200*1e200` overflow to Inf must error, not return Inf. Tiny values 1e-9, 1e-12 must still succeed.
- **Error substring contract** expanded: radius invalid → "radius", etc., plus IsNaN/IsInf usage enforced via AST (must use math.IsNaN/IsInf at least 2 times each).
- **Height inverse trap** kept: Object.Density() must NOT check Height (Height=0 should return 1 not error), Validate() must check Height.
- **DRY nudge** strengthened: instruction says "consider reusing Validate() for DRY" but blindly doing so fails Volume() Mass=0 and Density() Height=0 traps.

**Step2 (2_partial_submersion):** Uniform fluid prismatic (constant A=Vol/Height), conical apex-down (similar cones, non-linear depth via `d=H*cbrt(fraction)`, not linear), frustum bucket (R1 bottom, R2 top, package-defined linear radius interpolation `r(z)=R1+(R2-R1)*z/H`, cubic Volume=πH/3*(R1^2+R1R2+R2^2) via monotonic root-finding) PLUS stratified ocean where density `rho(z)=S+G*z` package-defined linear, buoyant mass integral `BM(d)=∫rho(z)A(z)dz` requiring derivation of `A(z)` per shape (prismatic constant, conical via similar triangles ∝z^2, frustum via linear r(z) → πr(z)^2). Per-shape BM(d) yields polynomial orders: quadratic for prismatic (S*d+0.5*G*d^2), cubic+quartic for conical (S*d^3/3+G*d^4/4), quartic mixing R1/deltaR/S/G for frustum. Bespoke reduction invariants: `G=0→uniform` within 1e-6, `R1==R2` cylinder linear, `R1==0` cone, monotonicity, nil→non-nil empty slice via explicit `make(...,0)` Go idiom, order preservation via Index field.

**Step3 (3_compressible_dynamics):** Compressible dynamics with hydrostatic pressure derived from density integral `P(z)=∫rho(z')g dz' = g*(S*z+0.5*G*z^2)` (must include 0.5 factor, discriminates naive `rho*g*z`), bulk-modulus linear compression `V(z)=V0*(1-P/K)` clamped to `MinimumVolumeFraction=0.1` with package constant reference requirement (AST check, not hardcoded 0.1), crush depth handling with 90% threshold (`depth>=0.9*CrushDepth` → CrushRisk=true, State="crush") and 'crush' error substring, buoyant force `rho(z)V(z)g`, quadratic drag opposing motion with **bespoke reference area `Ad(z)=V(z)/Height`** (not standard cross-section) and sign handling via `v*|v|`, terminal velocity from `Fnet=0` with sign matching `Fw-Fb`, equilibrium depth solving `M=rho(z)V(z)` via bisection with tolerance param, and time-to-depth via 4th-order weighted incremental integration (classic RK4 with Butcher [0,0.5,0.5,1] but with package-specific depth clamping during sub-steps to avoid negative depth errors) and linear interpolation. Concurrent batch `BatchFindEquilibrium` and `BatchTimeToDepthConcurrent` with order preservation, explicit nil→non-nil empty slice, race-free `sync.WaitGroup`+`sync.Mutex`, `go test -race` must pass. Reductions: `K→∞` approaches stratified incompressible, `G=0+K→∞` approaches uniform.

Why naive implementations fail (hardened v2): simple density equality misses tolerance boundary tests (0.9*Tol vs 1.1*Tol); missing Pi gives 3.14x error for cylinder (R=1,H=1 → π vs 1) and 0.75x for sphere missing 4/3; diameter vs radius confusion gives 4x (cylinder) /8x (sphere) error; linear cbrt missing fails 0.125→0.5H 4x trap; frustum requires cubic bisection; stratified requires deriving A(z) and integrating rho(z)A(z) yielding up to quartic plus 0.5 factor trap (S=1000,G=2,d=10 → 10100 vs 10200 1% error); pressure integral requires 0.5 factor; volume compression without clamping gives negative volume and missing MinimumVolumeFraction constant reference fails AST; crush handling missing 90% threshold; drag sign without v*|v| fails; Euler instead of RK4 fails accuracy test (Euler error >25% vs RK4 dt/10, tolerance ±15%); overflow missing returns Inf not error for 1e200*1e200; tolerance-zeroing missing returns epsilon not 0 for apparent weight/ballast within Tol; batch missing nil→non-nil empty fails; missing WaitGroup+Mutex fails race; DRY trap fails Volume() Mass=0 and Density() Height=0.
